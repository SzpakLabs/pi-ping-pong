# Separate Headless Reviewer

Worker implements and runs ordinary tests. Core invokes one separate read-only Reviewer after actual Worker results (or concrete reconciliation events), then validates and chooses the next state. No separate evaluator/preflight, source repair, or mandatory pre/post repeats. Chat A is the human command/report surface, never Core or this Reviewer.

## Configuration and operation

New configs: protocol_version=2, schema_version=1, review_transport=pi, review_execution=headless, explicit review_provider/review_model. The Reviewer model may differ from Chat A; launcher must not overwrite it. Omitted/chat execution retains the launching-chat transport for new evaluator-free configs only. Old evaluator-era configs/runs cannot resume; their files remain unchanged. See [migration](evaluator-preparation.md).

Core acquires its execution lease, durably records the dispatch attempt, and starts fresh ordinary Pi RPC with read-only tools and explicit provider/model/session. Automatic extension loading, MCP, skills, prompt templates, and repository context are disabled. Explicit `reviewer_extensions` can register providers and execute with this process’s privileges; load only trusted code. Actual RPC identity must match configuration and differ from Chat A/Worker. It reuses installed authentication without copying secrets. Startup, response and bounded same-session response-format repairs share the original finite review_seconds; Worker wall/token/iteration budgets remain separate. Cancellation/integrity checks run during RPC waits.

Core delivers the full TASK text and current contract/checkpoint inline in the Reviewer prompt; they are not merely file paths or claims of reads. Request/context and immutable evidence remain available through the read tool. For Git targets the request also binds a hash-checked `launch-diff.txt` (start→current lines of files dirty/untracked at launch; see [Git launch record](project-workspace.md#git-launch-record-and-startcurrent-diff)). It is a Core fact, not a verdict: unjustified removal of user launch lines is a concrete defect, while absent/partial coverage stays unknown. Reviewer uses retained ordinary test output and relevant source/artifacts. Use deterministic results for what they establish; do not rerun or re-prove them. Judge remaining requirement fit, visual/semantic quality, meaningful omissions and concrete defects only. Missing evidence stays unknown, not pass or a manufactured Worker correction. No direct product edits, shell/Worker launch, budgets or human approval authority.

Reviewer returns decision=endorse|halt|stop and feedback. Endorse additionally requires `assessment` with the **existing** action/criterion report fields. Core binds run/cycle/review/state/target/request/evidence identity, validates a copy, records then applies the report. Endorse is not finish. Concrete corrections and unfinished authorized work can use an evidence-backed `continuation` or justified experiment; generic feedback or unknown evidence alone cannot trigger either. See [full schema and decisions](action-scoped-protocol.md).

## Evidence and failure

Each request.evidence_archive value is the complete immutable FILE path; never append the logical key. Read relevant material evidence, not every unrelated attachment. Correlated read start/end events and `reviewer-reads.json` remain audit evidence, not a blanket mandatory reread/retry loop. An observed unsuccessful read of material cited for a verified claim (without later successful access) prevents that endorsement and leaves the work unverified; it does not trigger another Reviewer, a read-event retry loop or a Worker defect. A missing read event alone is not failure, and inline TASK needs no duplicate read: `reviewer-reads.json` lists it under `inline`, not `required`/`missing`. The hash-bound `launch-diff.txt`, when present, is listed under `optional`: an actual read appears in `succeeded` (or `errors`), it is never `missing`, and citing `launch-diff` is checked like other cited material. Prefix @ is stripped once before home/cwd resolution. Reads prove access, not comprehension, completeness or semantic/visual correctness.

Malformed model responses can be repaired within the same Reviewer session and deadline. A final assistant API error or abort after Pi settles is treated as unavailable, not malformed JSON. A valid negative assessment is never retried to seek a pass. Missing/failed review evidence must be reported unverified, not fabricated accepted. Reviewer unavailability/exhaustion retains existing work and permits eligible independent actions around the affected action/dependency/operation holds, then delivers available results with exact limitations. Existing genuine blockers are still grouped and delivered alongside the unverified result, without inventing a new human gate from the Reviewer failure. Goal budget-limited workspace results are preserved even when the first review fails. No evaluator repair, forced new review, new Worker allowance or routine human confirmation. Durable attempted reviews lacking disposition forbid blind redispatch, even when a response file exists.

Owned process-group cleanup preserves PID identity; inherited lease refuses overlap with an orphan Reviewer. These are cooperative host boundaries, not an OS sandbox against malicious same-UID tools. Never read credentials. No authority for paid models or new live tests comes from the adapter itself.

## Chat A reports and receiver

Chat A receives passive actual Worker/Reviewer-start notices and Core reporting requests via the existing private Pi inbox and durable receipts. It narrates the actual result without decisions, task repair, grants, human-input fabrication or Worker launches. State-report envelopes may coalesce pending same-run/session state reports; human questions/reviews are never superseded. Reporter enqueueing is not acceptance or exactly-once model output. Reporter usage is separate from Worker/Reviewer budgets.

Reports use standalone STATUS and separate TL;DR, Summary, Report, Suggested action, Full run status headings with blank lines. Start with current bridge-status plus supplied compact Core facts; healthy matching terminal results need no extra reads. Explain delivered versus accepted/unverified, real human needs, and whether a stage actually started. Unknown evidence/internal role failures are not human approval gates. Final delivery failure must not erase independently accepted work. See [report format](../references/reviewed-runs.md#human-facing-report-formatting).

Resource/event waits remain distinct from human waits; reminders use no model turns. Existing aliases, receiver session entries/identity, read-only status, duplicate-launch refusal, `/ppp-respond` addressed text/native confirmation and advanced JSON stay compatible. Session reopening restores monitoring, not execution replay. UI-close autonomy, arbitrary other-chat access and cross-chat catch-up remain deferred, not claimed by local fixtures.

Artifacts: context/request/review JSON, immutable evidence, reviewer.json (actual provider/model/session/lifecycle), reviewer-sessions/, reviewer stderr/stdout, bounded response attempts/results, read audit, durable dispatch attempt/receipt. No eval.stdout, evaluator source or evaluator revision journal is created. Artifact existence alone is not acceptance; missing usage is unknown, never zero or actual subscription billing. Current fake-process/unit checks do not establish live model correctness; new live tests require authorization.
